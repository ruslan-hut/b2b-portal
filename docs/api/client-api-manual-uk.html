01Увімкнути доступ

Доступ до API вмикає ваш менеджер — за замовчуванням він вимкнений. Напишіть менеджеру, що плануєте інтеграцію, і він відкриє API для вашого облікового запису.

Після цього увійдіть у портал під своїм звичайним логіном і відкрийте Профіль (/profile). Унизу сторінки з’явиться розділ «Доступ до API». Якщо розділу немає — доступ ще не увімкнено; вийдіть і зайдіть знову, а якщо не з’явився, зверніться до менеджера.

Хто що робить. Менеджер відкриває доступ один раз. Ключі ви створюєте, замінюєте й відкликаєте самостійно — звертатися до нас за цим не потрібно.

02Створити ключ

Натисніть «Новий ключ» і заповніть форму:

Дозволи (scopes)

Давайте ключу лише те, що потрібно саме цій інтеграції.

ДозвілЩо відкриває
catalog:readкаталог, картка товару, розрахунок замовлення (quote)
orders:readсписок і картка замовлень, статуси, накладні, трекінг
orders:writeстворення замовлень
profile:readпрофіль і адреси доставки
profile:writeредагування профілю та адрес

Ключ показується один раз

Ключ має вигляд cmx_<режим>_<префікс>_<секрет>. Режим — live або test. Префікс із 8 символів публічний: за ним ключ видно у списку й у логах, і саме його називайте в листі до підтримки. Секрет ми не зберігаємо у відкритому вигляді й відновити не можемо.

Почніть із тестового ключа. Поставте позначку «Тестовий режим» — такий ключ читає дані як звичайний, а POST /orders проходить усю перевірку й розрахунок, але нічого не зберігає. Коли інтеграція готова, створіть окремий бойовий ключ.

03Перший запит

Найпростіша перевірка — GET /me. Вона не потребує жодного дозволу й одразу показує, чи ключ живий і що саме йому дозволено.

GET/me · curl
curl -s https://b2b.darkbyrior.com/api/client/v1/me \
  -H "Authorization: Bearer cmx_test_Ab3dEf9h_…"

Ключ можна передавати і заголовком X-API-Key — це рівноцінно.

200 OKвідповідь (скорочено)
{
  "success": true,
  "data": {
    "client": { "uid": "c-1f4a…", "name": "Студія «Ажур»", "phone": "+380671234567" },
    "currency": { "code": "UAH" },
    "vat_rate": 20,
    "addresses": [ { "uid": "a-88c1…", "is_default": true, "city": "Київ" } ],
    "api_key": {
      "name": "Наша ERP",
      "scopes": ["catalog:read", "orders:read"],
      "is_test": true,
      "expires_at": "2027-08-17T10:00:00Z",
      "rate_limit_read_per_minute": 600,
      "rate_limit_write_per_minute": 60
    }
  },
  "request_id": "req_9f2c…"
}

Кожна відповідь має однакову оболонку: success, далі data або error, і request_id. Той самий ідентифікатор повертається в заголовку X-Request-ID — логуйте його у себе, з ним ми знайдемо будь-який ваш запит за секунди.

Отримали 401? Це єдина відповідь на всі причини — невідомий ключ, відкликаний, прострочений або вимкнений доступ. Перевірте, що скопіювали ключ повністю, що він не відкликаний у профілі, і що менеджер увімкнув доступ. Після кількох невдалих спроб поспіль (20 за 10 хвилин) ваша IP-адреса тимчасово блокується — зачекайте час із заголовка Retry-After.

04Каталог і ціни

Каталог уже приведений під вас: у ньому лише товари з ціною для вашого прайсу, дозволені до продажу у вашій країні. Ціни — у копійках/центах, цілим числом.

GET/catalog/products
curl -s "https://b2b.darkbyrior.com/api/client/v1/catalog/products?limit=2&search=gel" \
  -H "Authorization: Bearer $COMEX_KEY"
200 OKмасив товарів
{
  "success": true,
  "data": [
    {
      "uid": "p-7b21…",
      "sku": "DBR-1042",
      "barcode": "4820001234567",
      "name": "Gel Polish 8 ml, відтінок 042",
      "base_price": 18000,          // 180.00 без знижки і ПДВ
      "price_with_discount": 16200,
      "price_final": 19440,         // зі знижкою і ПДВ — це те, що заплатите
      "vat_rate": 20,
      "discount_percent": 10,
      "available": true
    }
  ]
}
ПолеЗначення
base_priceціна до знижки й без ПДВ
price_with_discountзі знижкою, без ПДВ
price_finalзі знижкою і з ПДВ — сума до сплати за одиницю
availabletrue, якщо товар є на складі для вас

Залишків API не показує — лише ознаку available. Якщо потрібної кількості не вистачає, ви дізнаєтесь про це під час розрахунку замовлення.

Зіставлення за вашими артикулами

Щоб не тягнути весь каталог, надішліть свої SKU або штрихкоди — у відповідь отримаєте товари з цінами й окремий список not_found.

POST/catalog/products/lookup
curl -s https://b2b.darkbyrior.com/api/client/v1/catalog/products/lookup \
  -H "Authorization: Bearer $COMEX_KEY" \
  -H "Content-Type: application/json" \
  -d '{"skus":["DBR-1042","DBR-9999"],"language":"uk"}'

Також доступні /catalog/categories, /catalog/languages, картка товару за uid або за артикулом (/catalog/products/by-sku/{sku}) та її зображення.

05Замовлення

Спершу розрахунок, потім створення. Тіло запиту в обох випадках однакове, тому перехід від перевірки до бойового замовлення — це зміна одного рядка URL.

POST/orders/quote · нічого не зберігає
curl -s https://b2b.darkbyrior.com/api/client/v1/orders/quote \
  -H "Authorization: Bearer $COMEX_KEY" \
  -H "Content-Type: application/json" \
  -d '{
        "items": [
          {"product_uid": "p-7b21…", "quantity": 6},
          {"product_uid": "p-3c08…", "quantity": 2}
        ],
        "client_reference": "PO-2026-118",
        "comment": "Відвантажити разом із попереднім"
      }'
200 OKрозрахунок
{
  "success": true,
  "data": {
    "quote": true,
    "items": [ { "product_sku": "DBR-1042", "quantity": 6, "total": 116640 } ],
    "subtotal": 129600,
    "total_vat": 25920,
    "delivery_cost": 0,
    "total": 155520,
    "currency_code": "UAH"
  }
}

Суми сходяться так: total = subtotal + total_vat + delivery_cost (доставка не входить ані в subtotal, ані в total_vat).

Створення замовлення

Той самий запит на POST /orders створює підтверджене замовлення: воно одразу з’являється в роботі у менеджера. Обов’язково додайте заголовок Idempotency-Key — з ним повторна спроба після обриву мережі не створить друге замовлення.

POST/orders · потрібен orders:write
curl -s https://b2b.darkbyrior.com/api/client/v1/orders \
  -H "Authorization: Bearer $COMEX_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: PO-2026-118" \
  -d '{"items":[{"product_uid":"p-7b21…","quantity":6}],
       "client_reference":"PO-2026-118"}'
  • 201 — замовлення створено, у відповіді uid і number.
  • 200 з "test": true — тестовий ключ: усе перевірено й пораховано, нічого не збережено.
  • 409 — той самий Idempotency-Key надіслано з іншим тілом.
  • Повтор із тим самим ключем і тим самим тілом протягом 24 годин поверне ту саму відповідь із заголовком Idempotent-Replayed: true.

Адреса доставки береться з вашої основної, якщо не передати shipping_address_uid. Поле client_reference — ваш власний номер (PO): він зберігається, показується менеджеру й за ним можна шукати замовлення.

Якщо замовлення відхилено

400відхилення
{
  "success": false,
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Order rejected",
    "details": { "reason": "insufficient_stock" },
    "extra": { "problems": [ { "product_uid": "p-3c08…", "reason": "insufficient_stock" } ] }
  }
}

Типові причини у details.reason: validation (проблеми по рядках — у extra.problems), insufficient_stock, address_invalid, business_registration_required.

06Код: Python і Node

Pythonrequests
import os, requests

BASE = "https://b2b.darkbyrior.com/api/client/v1"
S = requests.Session()
S.headers.update({"Authorization": f"Bearer {os.environ['COMEX_KEY']}"})

# 1. перевірка ключа
me = S.get(f"{BASE}/me", timeout=15).json()["data"]
print(me["client"]["name"], me["api_key"]["scopes"])

# 2. знайти товар за своїм артикулом
found = S.post(f"{BASE}/catalog/products/lookup",
               json={"skus": ["DBR-1042"]}, timeout=15).json()["data"]
product = found["products"][0]

# 3. створити замовлення (повтор безпечний завдяки Idempotency-Key)
r = S.post(f"{BASE}/orders",
           headers={"Idempotency-Key": "PO-2026-118"},
           json={"items": [{"product_uid": product["uid"], "quantity": 6}],
                 "client_reference": "PO-2026-118"}, timeout=30)

body = r.json()
if not body["success"]:
    raise RuntimeError(body["error"]["message"], r.headers.get("X-Request-ID"))
print("замовлення", body["data"]["number"], body["data"]["total"] / 100)
Node.jsfetch (18+)
const BASE = "https://b2b.darkbyrior.com/api/client/v1";

async function call(path, init = {}) {
  const res = await fetch(BASE + path, {
    ...init,
    headers: {
      Authorization: `Bearer ${process.env.COMEX_KEY}`,
      "Content-Type": "application/json",
      ...init.headers,
    },
  });
  const body = await res.json();
  if (!body.success) {
    // request_id варто записати в лог — з ним ми знайдемо запит
    throw new Error(`${body.error.code}: ${body.error.message} (${body.request_id})`);
  }
  return body.data;
}

const quote = await call("/orders/quote", {
  method: "POST",
  body: JSON.stringify({ items: [{ product_uid: "p-7b21…", quantity: 6 }] }),
});
console.log("до сплати:", quote.total / 100, quote.currency_code);

503MAINTENANCEпланові роботи — повторити пізніше

Обмеження частоти

На ключ діють два ліміти: 600 читань і 60 записів за хвилину (можемо змінити на запит). Кожна відповідь несе X-RateLimit-Limit і X-RateLimit-Remaining; відмова — Retry-After і X-RateLimit-Reset.

  • Тіло запиту — до 1 МіБ, таймаут — 10 секунд.
  • Списки посторінково: offset і limit (максимум 100).
  • На 429 і 5xx робіть повтор із витримкою; на 4xx повтор не допоможе.

08Безпека ключів

  • Ключ = доступ до ваших цін і замовлень. Тримайте його в змінних оточення або сховищі секретів, не в коді й не в репозиторії.
  • Ніколи не використовуйте ключ у браузері чи мобільному застосунку — лише на вашому сервері.
  • Окремий ключ на кожну систему: тоді відкликання одного не зупиняє решту.
  • Ключ дійсний 365 днів. Стежте за датою в профілі — ми попереджаємо менеджера заздалегідь.

Замінити ключ (кнопка «Замінити новим ключем») видає новий і залишає старий робочим ще на короткий пільговий період — 24 години. Це штатний спосіб оновлення без простою: створіть новий, оновіть налаштування у себе, дочекайтесь, поки трафік перейде.

Відкликати — миттєво й безповоротно: усе, що використовує цей ключ, одразу перестає працювати. Так і треба робити, якщо є підозра, що ключ витік.
